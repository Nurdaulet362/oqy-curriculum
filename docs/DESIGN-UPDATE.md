## Область работы

Дизайн развивается в рамках существующей светлой зелёно-оливковой палитры. Приоритет — методист, который читает результаты, сравнивает темы и составляет план. Применяется режим Operate: знакомые элементы управления, ясная иерархия и читаемые данные важнее декоративных эффектов.

В `src/App.tsx` добавлены переход с клавиатуры к основному содержимому, состояние активного раздела для вспомогательных технологий, раскрытие подробностей рядом с выбранной темой и возврат фокуса при закрытии. Поле бюджета сопровождается подсказкой; таблицы имеют названия по назначению и подсказку горизонтальной прокрутки. Списки доступных предметов, классов и школ вычисляются только при изменении соответствующих данных, а не при каждом вводе бюджета.

В `src/styles.css` объединены правила визуальной системы: основной текст 13–14px, обычные подписи данных 12px, элементы управления от 44px, согласованные состояния и табличные цифры. Показатели объединены в сводную полосу. На планшете навигация переходит наверх; на телефоне название темы и процент располагаются над полосой графика. Таблицы сохраняют отдельную область прокрутки. Внешние шрифты и сетевые ассеты не добавлены.

Визуальная система описана в [DESIGN.md](DESIGN.md). Установка навыков сама по себе не подтверждает качество или работоспособность приложения.

## Проверка обновления

После обновления прошли production-сборка, 27 unit-тестов, 3 проверки упаковки и сверка сохранённых расчётных артефактов с текущим кодом. На собранной версии проверены 11 этапов E2E и 8 сценариев строгого браузерного аудита. Проверка доступности выполнила 10 сканирований без найденных axe-нарушений и 9 проверок взаимодействия. Фактические результаты: [e2e.json](../artifacts/e2e.json), [audit-browser.json](../artifacts/audit-browser.json), [accessibility.json](../artifacts/accessibility.json).

Дополнительная проверка обновлённого дизайна на production-сборке прошла **27 проверок**, ошибок JavaScript страницы — **0**. Она охватывает клавиатурную навигацию, раскрытие и закрытие темы, активный раздел, узкие и промежуточные размеры, длинные названия и уменьшение движения. Отчёт: [design-check.json](../artifacts/design-check.json).

Визуально просмотрены обзор на компьютере и телефоне, а также мобильный план. Браузерные и автоматические проверки подтверждают перечисленные сценарии, но не заменяют пользовательскую проверку и не доказывают педагогическую эффективность.

Ручной запуск детектора Impeccable выдал **150 рекомендательных замечаний**: 81 по палитре, 55 по шкале шрифта, 14 по радиусам. Замечаний вне категории advisory не было. Это не «чистый» результат детектора: он выявил, в частности, буквальные несовпадения с краткой спецификацией — эквивалентные размеры px/rem, оттенки состояний и различия формы знака, графика и панелей. Эти случаи просмотрены; полная шкала размеров и семантические исключения отражены в DESIGN.md. Исходный отчёт и решение ручного просмотра: [design-detector.json](../artifacts/design-detector.json).

## Воспроизводимость

Основные проверки проекта: `npm test`, `npm run build`, `npm run test:package`, `node scripts/generate-evidence.mjs --check`. При работающем приложении доступны `npm run test:e2e`, `npm run test:strict`, `npm run test:a11y` и `npm run test:design`; переменная `OQY_BASE_URL` задаёт адрес проверяемой сборки.

`npm run package` формирует автономный демонстрационный комплект `release/OQY-demo.zip`. Исходный комплект создаётся из финального коммита отдельно:

```sh
git archive --format=zip --prefix=OQY-source/ --output=release/OQY-source.zip HEAD
```

В исходный ZIP входят только файлы финального коммита. Поэтому обновлённые исходники, документация и результаты проверок должны быть сохранены в Git до выполнения команды.
