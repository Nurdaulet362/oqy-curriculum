# Кейс и границы решения

## Источники

Исходный документ `Кейс 1.docx` (имя файла в рабочей папке может содержать составной символ «й») и изображение `2026-11-11 09.04.36.jpg`. Документ содержит формулировку на русском и казахском; изображение повторяет русскую задачу и главную ценность. Дополнительных критериев оценки, форматов сдачи или данных в них нет.

**Задача:** разработать EdTech-платформу для методистов, которая анализирует результаты тестирования школьников и помогает принимать обоснованные решения об учебниках и учебных часах.

**Пользовательский результат OQY:** методист загружает CSV или Excel `.xlsx` и получает темы для внимания, сопоставление учебников и проверяемый проект учебного плана.

## Связь требований и реализации

| Явное требование кейса | Решение | Что показать жюри |
| --- | --- | --- |
| Анализ по отдельным темам | Нормализованные результаты и объём данных по теме | Тема, средний балл, доля освоения, медиана и разброс |
| Выявление сложных разделов | Приоритет темы по результатам тестирования | Раздел с низким результатом и исходным числом наблюдений |
| Сравнение эффективности учебников | Сравнение наблюдаемых результатов на общих темах | Общие темы и среднее с одинаковым весом тем |
| Обоснованные рекомендации по часам | Перераспределение целого бюджета на основе трудности | Текущие и предложенные часы, поиск и сортировка тем, точная итоговая сумма |

Слово «эффективность» в кейсе не даёт оснований заявлять причинный эффект по одним результатам тестирования. В проекте показывается сравнительная статистика с явным ограничением.

## Допущения прототипа

- Демонстрация использует синтетический набор, потому что организаторские данные не приложены.
- Вход — CSV или один выбранный лист Excel `.xlsx` с результатами по теме; подключение школьных информационных систем не требуется для демонстрации.
- 70% выбраны как порог освоения для MVP. Это изменяемая продуктовая гипотеза, не требование кейса.
- Средние по темам рассчитываются после нормализации каждого балла по его максимуму. Нормализация шкалы сама по себе не выравнивает сложность заданий.
- В сравнении учебников общие темы равновесны. Отличия школ, учеников и учителей сохраняются как потенциальные смешивающие факторы.
- Алгоритм планирования сохраняет заданный бюджет и минимум один час на тему. Вес равен `текущие часы × (1 + 3 × (100 − средний балл) / 100)`; после выделения минимума остаток распределяется пропорционально весам с методом наибольших остатков. Коэффициент 3 — эвристика, её полезность требует контролируемого пилота. Предметные минимумы, зависимости тем и нормативы учебного плана должны добавляться перед внедрением.
- Решение методиста остаётся окончательным. Алгоритм не меняет официальный учебный план автоматически.
- Приложение выполняет импорт и расчёты локально в браузере. Совместная работа, авторизация и долгосрочное хранение не входят в MVP.
- Генеративная модель не нужна для вычисления показателей; рекомендации воспроизводимы, не требуют API и не добавляют расход на запросы.

## Срок и канал

Участник подтвердил дедлайн «сегодня»: **11.11.2026, Asia/Almaty (UTC+5)**. Точный час неизвестен. Форму участник заполняет и отправляет самостоятельно. Известно требование участника создать приватный GitHub-репозиторий; публикация исходников в открытый доступ не разрешена.

## Условия готовности комплекта

- Проект запускается по README и содержит рабочий демонстрационный набор.
- Основной сценарий проходит от данных к сравнению и плану часов.
- Неверные данные получают понятную ошибку; корректный набор не теряется.
- Расчёты и сохранение бюджета проверены тестами.
- Production-сборка создаётся; презентация открывается без внешних ресурсов.
- В итоговом отчёте различаются проверенные результаты, ограничения и предполагаемые будущие улучшения.
- В приватном репозитории или передаваемом архиве нет ключей и реальных персональных данных.
- Факт отправки формы подтверждает участник, а не наличие подготовленного комплекта.


## Расширение релиза

Импорт Excel, интерактивные таблицы и описательная статистика поддерживают тот же сценарий методиста. Поиск в таблице не пересчитывает бюджет и не сокращает выгружаемый план. Новые статистические показатели объясняют распределение наблюдений и не добавляют причинных выводов. Подробные ограничения и статус проверки: [FEATURE-UPDATE.md](FEATURE-UPDATE.md), [DATA.md](DATA.md), [VALIDATION.md](VALIDATION.md).
