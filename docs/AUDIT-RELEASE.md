## Найденные дефекты и исправления

### R1 · P2 · Повторная упаковка включала старые файлы

В исходном `scripts/package.mjs:5–6` существующая папка `release/OQY` переиспользовалась через `mkdirSync` и `cpSync`. Эти вызовы не удаляют файлы, отсутствующие в новой сборке. При переименовании JS/CSS старый файл остаётся в следующем архиве; аналогично остаются другие файлы предыдущего комплекта.

Воспроизведение проведено в отдельной временной папке: создать `release/OQY/dist/old-build.js`, затем запустить исходный скрипт с новой папкой `dist`, где такого файла нет. В полученном ZIP присутствовал `OQY/dist/old-build.js`. В уже переданном первоначальном ZIP лишних старых JS/CSS не обнаружено; воспроизведён дефект повторного выпуска, а не фактическая утечка пользовательских данных.

**Исправлено в скрипте:** каждый пакет формируется в новой временной папке; ZIP публикуется атомарным переименованием только после полного формирования. При ошибке сохраняются предыдущий ZIP и развёрнутая папка. Символические ссылки отклоняются, чтобы не упаковать данные за пределами комплекта. После перевыпуска нужно перезапустить сервер, если он обслуживал старую папку `release/OQY/dist`.

### R2 · P2 · Хеш двигателя в сохранённых доказательствах не соответствовал сдаваемому исходнику

`artifacts/benchmark.json.workload.engineSha256` и `artifacts/demo-report.json.source.engineSha256` указывали `981d53edf688b1183c1ee80c0649eabafe9efa77422a4de3ef6aa25a9287b64c`. SHA-256 `src/lib/analytics.ts` в проверяемой версии — `47adc6eacaddb23f1e0b065da8da7fd8162a45edbb028a429dfa8bda9b5c5b8c`.

Исходный CSV совпадает по хешу. Несовпадение двигателя само по себе не доказывает неверность чисел — оно может возникнуть после форматирования, — но лишает сохранённый результат заявленной привязки к сдаваемому файлу. Следует заново сформировать benchmark и отчёт после завершения правок двигателя, затем обновить соответствующие контрольные суммы. Перегенерацию доказательств и финальную сверку выполняет основной агент вместе с интеграцией остальных исправлений.

Дополнительно новый пакет содержит `VERSION.json`: Git commit (либо `null` для исходного ZIP без `.git`), признак незакоммиченных изменений и SHA-256 фактически включённых файлов сборки. Коммит при `sourceDirty: true` обозначает базовую версию, а не точную неизменённую рабочую копию.

### R3 · P2 · Инструкции и пути исходников выдавались за содержимое готового демо

В первоначальном демо ZIP корневой `README.md` рекомендовал `npm ci` и `npm run dev`, но `package.json` в этом комплекте отсутствовал. Рабочая инструкция через Python находилась отдельно в `START-HERE.txt`. Кроме того, включённый исходный `artifacts/submission-manifest.json` ссылался на `public/data/demo.csv` и `public/pitch.html`; в демо фактические пути — `dist/data/demo.csv` и `presentation.html`/`dist/pitch.html`. Проверка исходного manifest по путям из корня демо не могла пройти.

**Исправлено в скрипте:** корневой README теперь описывает запуск конкретного готового комплекта через Python, а исходная инструкция сохраняется под явным именем `SOURCE-README.md`. Создаётся отдельный `MANIFEST.json` с путями относительно распакованной папки OQY и хешами всех файлов, кроме самого manifest. Исходный manifest не переименовывается и остаётся справочным артефактом исходного проекта.

## Соответствие кейсу и ограничения

Документ и изображение требуют анализ тем, поиск сложных разделов, сравнение учебников и обоснованное распределение часов. Продукт покрывает эти четыре направления. В источниках нет обязательного требования использовать LLM, разворачивать сервер или предоставлять совместное редактирование. Их отсутствие не отмечалось как дефект.

В документации корректно обозначены синтетические данные, наблюдательное сравнение, эвристический коэффициент распределения и отсутствие доказанного улучшения обучения. Дедлайн известен только как дата; отправку формы выполняет участник. Выступление человеком ещё нужно отрепетировать. Приём заявки организаторами этим аудитом не подтверждается.

Многопользовательский доступ, интеграции с реальными школьными системами, организационные правила работы с данными и предметные нормативы часов остаются за границами локального MVP. Отсутствие серверной авторизации не является уязвимостью текущей архитектуры: у неё нет серверного хранилища загруженных результатов.
